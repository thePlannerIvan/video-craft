# 画面与动画：先对齐动作，再扩展制作

制作方案阶段读取；不要把完整动画做完后才发现作者说的是另一种动作。

## 只讨论真正改变成片的分歧

先沿用当前已确认的画幅、交付形态、人物与画面主次、声音归属。未知且会造成返工时，给出少量具体选项与推荐，最好用同一素材的画面比较。比如“画面为主＋角落人物 / 全屏人物与画面切换 / 分开交付”；不凭“照以前”自行发明组合。

已有录音时先产出带实录声音的代表片段，覆盖关键画面关系和最容易误解的动效。无录音时依制作计划用明确标注的预演声音。审的是观众实际看见、听见的结果，而不是只审文字脚本、人物剪切页或无声动图。审阅入口见[review-ui](review-ui.md)。

## 一个动画说清四件事

在现有 production-plan 对应段落写 **起始画面 → 发生什么变化 → 结束画面与停留 → 口播触发点**，不额外建一套长文档。材料中谁保持不动、谁移动、谁被遮罩/揭示必须明确。用首/中/尾状态图或一个短片澄清歧义，例如“页面整体移出”与“页面不动、遮罩边界移动”是两种不同动作。

动画要表达比较、数量变化、顺序、关系或注意力转移；静态页面可以停住供阅读。缩放、留白、人物位置都服从本片意图和作者决定，不从单次反馈推出永久禁令。

录屏先看候选窗口的连续帧，再定源区间、裁切与变速。核对需要的输入框、正文、用户名在整个区间都可见，且画面确实出现要展示的变化。画面差分只能帮助定位活跃区，不证明变化有意义；不能仅按文件开头或某一帧的好看程度选片。

## 对齐到一句话，而不只是一个 Beat

关键出现/消失、揭晓完成、CTA 切换记录触发原句及其实际 cue/词位置，再派生时间。一个画面落在正确 Beat 内不代表出现时机正确。允许已设计的提前呈现或声音桥接，但要写明意图；作者指定“说到这句才出现”就按那句校准。

改动镜头顺序、时长或口播后，更新同一时间来源，重验受影响的窗口及前后衔接。不要分别手改字幕、审阅页和动画里的时间。

## 动起来不等于做对了

check_motion 只证明抽样窗口存在像素变化，不能证明方向正确、循环完整、结尾抵达或中途不卡住。对实际编码后的关键动画，检查起点、变化中段、循环交界、最后一次变化和结束停留；局部失败重做局部。多轮动画尤其核对第二轮及最后一轮，不只看首中尾三个全片截图。

工具只证明它实际检查的性质：文字词表未命中不等于没有制作备注，字幕检测通过不等于自然断句。最终带声片段仍要看读听。页面正文、图表原文等作者有意展示的内容，不因触及检查关键词就自动删除。
