# Caption Modes & 字幕制作（v2.2）

字幕处理有三个模式，**必须在 Checkpoint Plan 时向用户问一次**，不要默认内嵌。

## 三种模式（caption mode）

| 模式 | 含义 | 适用 |
|---|---|---|
| `embed` | 字幕作为 composition 内 clip（如 `.caption` 层），渲染进 MP4 | 发布即最终成品，不经过剪辑软件 |
| `srt-deliver` | composition 无字幕层，交付 `captions.srt`（词级时间戳）给用户导入剪辑工具 | 用户还要剪/套样式的场景 |
| `both` | 内嵌烧录 + 同时交付 SRT | 平台发布 + 用户后续复用 |

决策记录到 `project.md`（`captionMode: embed|srt-deliver|both`）。

## 断句原则（用户口述，2026-08-01，最高优先级）

> "如果能够把字幕写成一篇顺畅的文章的话，那么从标点符号切分就是最好的，
> 字数大概在 10～18 个字之间，更长的话就考虑从中间的转折地方切开。"

> "有些句子字很少，比如四五个字，优先想一想能不能合并，如果句子的意思是
> 独立的就留着，能合并就合并，控制在十个字左右。"

落地规则（按优先级）：

1. **标点断永远优先**：句号/叹号/问号必断；逗号/顿号/分号/冒号在组 ≥5 字时断
2. **10-18 字区间**：目标每 cue 10-18 字（视觉宽度：汉字 1、拉丁 0.6）
3. **转折处切开**：超 18 字且无标点时，在句中的转折词（但/所以/因此/然而/
   不过/反而/于是/因为/如果/其实/而且/并且）**之前**切，转折词位置在
   6..len-6 区间内取最后出现的
4. **18 字兜底**：无标点无转折时按词累计 18 字切（带粘着词保护）
5. **短句合并**：4-5 字的 cue 先判断能否并入相邻 cue（语义连续就合并，
   目标 10 字左右）；**语义独立才保留**（独立引入语"第一次使用"、独立
   转折"但问题是"、独立短语"一来一回"、列举项拆分的短项）
6. **粘着词保护**：断点后紧跟 STICKY 词时把切点右移（把粘着词并入前组）：
   `儿子们得了着过呢吧啊呀么而就也还都又到把被跟和或以及虽然并却再更很最太挺后
   点下中源期似意单相题貌程科但产间事情形问重标准料文案板淀续合服觉要层样
   架味户库来及格线这有个东西分化地省件`
   （"AI味儿"、"写点方案"、"时间、资源"、"东西"、"出来"这类组合不许切开）
7. **剩余过短不切**：切点后剩余 <4 字 → 不切（继续累积），避免"东西/出来"
   被孤立；40 字绝对上限强制切
8. 断句后句首 lstrip `，、；：`，句尾 rstrip ` ，、；：`

## 词级重建脚本的实现要点（实测踩坑，逐条修复过）

词级 SRT 重建（Scribe word JSON + EDL 偏移累加）易错点：

1. **cut=0 重置组时间起点**（最严重）：18 字兜底切在组首（micro-break 点为 0）
   时，若照常把 `cur_s` 清空，下一词会重新设定组起点 → 组的文本包含更早的词但
   时间从断点处起（实测"我希望让经验丰富的老手…"整句时间错位到句尾）。修复：
   cut 必须 `> 0` 才生效，否则整组断
2. **micro-break 组首记录**：每组首词会因跨组 gap 记录 0 值；用
   `micro_breaks[-1] > 0` 过滤，否则 cut=0 阻断后续所有切分（整句攒到句号，
   产出 25-30 字长句）
3. **切点越界**：18 字整时累计切点落在组尾（cut == len(cur)）→ 不切，继续累积
   到下一词再试
4. **b2 首 in STICKY 或 b2 <4 字 → 不切**（继续累积），而不是强行切碎
5. **Scribe 时间重叠**：快速语音段词级时间互相重叠（后句词的 start 早于前句
   词的 end）→ 输出前线性化（每 cue start = max(自身, 前一 cue end)）
6. **零时长 cue**：Scribe 对句号/顿号输出 start=end；词级 join 时若组内所有词
   都零时长（整句压在一个时间点）→ 用组首词 start 与句末标点 time 重建
7. **总时长 cap**：任何 cue 的 end > EDL 总时长 → 丢弃并警告（实测出现超出
   0.7s 的尾部残留词）
8. **英文/数字连续**：相邻 latin 词不切（"Plan|as" 切碎会毁掉专名）

## 订正清单必须句级应用（实测踩坑）

FIXES（如 "PlanasProposalSystem"→"Planners-Proposal-System"）在**词级**
replace 会失效——ASR 分词把词切碎（"Plan"+"asProposalSystem"）后整串不存在。
修复：

- 先拼整句，再在**句级**套订正表（长目标串优先）
- 跨 cue 检测：相邻 cue 拼接后含目标串 → 合并替换（实测 "Skill。Plan" +
  "asProposalSystem。" 只有拼接后才能匹配）

已确认的订正实例（ProposalVideo 项目）：PlanasProposalSystem → Planners-
Proposal-System、PandasPPTHelp → Planners-PPT-Hell、节能目录 → 技能目录、
所以明明 → 所以秘密、这个事业上 → 这些事情上、固定的解所以 → 固定的解法。所以、
报所以 → 所以、方首先 → 首先、就这么简 → 就这么简单、可能人会（删）、
你你 → 你、比，你要 → 你要。

## 剪映/PR 导入空隙（实测踩坑）

cue 之间**首尾相接**（前句 end == 后句 start）导入剪映会挤坏。导出前给每个
cue（最后一个除外）的 end 缩短 0.04s，保证空隙 ≥0.03s；显示时长不足 0.3s
的 cue 保留保底时长。

## 人工复查门禁（必须）

脚本生成只是初稿——**逐条人工读一遍输出**（用户明确要求"自己看"），检查：

1. 断句自然（无拆词、无碎句、短句已合并）
2. 专名订正生效（跨词 fix 常见漏网）
3. 时间递增无重叠、无零时长、无超界
4. 抽样首尾各 5 条 + 中间所有长句

## 内嵌字幕（embed）视觉参数

- 字号 ≥ 画面宽的 1/20（1920 宽 → ≥78px；1080 宽 → ≥48px）
- 对比度 AA（深色底 rgba(10,10,10,0.74) + 白字；或主题 token）
- 行距 1.5、圆角 4px、居中、底部留白 40px（避让底部 UI）
- 分句优先短句：每 cue 1-2 行视觉长度
- 字幕 clip 用独立 track（如 `data-track-index` 从 20+ 起），与场景 clip 并行，不改场景时间轴

## 移除/重建字幕层的约定（实测踩坑）

composition 中字幕占三处，增删必须三处同步：

1. CSS 块（`.caption` / `.cap-inner` 样式）
2. DOM：每句一个 `<section class="clip" id="cap-NNN">`（放最后一个场景之后）
3. JS：`// ── captions ──` 到 `window.__timelines["main"] = tl;` 之间的 gsap fromTo/to

重建/批量修改时：**先把字幕数据导出成中间产物**（如 `tools/_captions_dom.txt` + `_captions_js.txt`），脚本化增删，改文本时只动中间产物再重新生成——不要直接手改 197 个 section。

注意：preview server 的 HMR 会往 DOM 注入 `data-hf-id` 属性，**精确字符串匹配会失败**；DOM 增删用宽松 regex 或按 index 定位，JS 块不受注入影响可用精确匹配。

## 文字稿订正（可选，需用户确认）

- 位置：Phase 0 handoff 之后、Checkpoint Plan 之前
- 做法：把完整文字稿（SRT 拼合）给用户看，收集订正清单，保存为 `input/fixes.txt`（每行 `原文|订正`）
- 时间戳不动，只改文本；订正后在 SRT 重建脚本中**句级**套用
- 用户不要求时不要主动订正（可能是有意的口语）

## 交付

- `srt-deliver` / `both`：SRT 交付到**项目根目录**（`<项目根>/captions.srt`，
  my-video 的上一级，与成片 mp4 放一起），cue 数、总时长打印在终端，
  抽查首尾各 2 条给用户；`input/subtitles.srt` 仍是流水线时间源，交付件
  复制到根目录而不是留在 work 目录里
- SRT 格式：`N\nHH:MM:SS,mmm --> HH:MM:SS,mmm\n文本\n`，UTF-8
- 交付前做**空隙检查**（剪映要求）
