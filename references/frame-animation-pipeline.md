# 自绘逐帧动画作为视觉层

视觉层不是现成素材、也不是 HyperFrames / Manim / Remotion，而是**用代码一帧一帧画出来**时走这条路线。
它适合：全片要一套自制的、可复用角色的美术语言；镜头多、时长长（2–5 分钟）；并且预期会有多轮逐画面返修。
**本文写的是流程与约束，不是某一种画风**——像素、剪纸、矢量扁平、手绘扫描都走同一条结构，换的只是绘制函数。

不适合：用现成素材就能讲清楚的段落，以及需要真实证据的画面（那是 [media-first](media-first.md) 的地盘）。

## 全景

```
口播定稿 → EDL 剪定 → 实测 segment_durations.json（唯一时钟）
                              │
                              ▼
                   切成 slot（通常一个 beat 一个）
                              │
              ┌───────────────┴───────────────┐
              ▼                               ▼
     slot_01 … slot_0N（各自独立渲染，无声 MP4）
              └───────────────┬───────────────┘
                              ▼
                    -c copy 拼接成整条视觉腿
                              ▼
        视觉腿（无声）+ 口播腿（带音轨）+ SRT ──► 成品/
```

## 帧数是合同（最硬的一条）

- 每个 slot 的帧数由实测时长乘 fps 取整得出；**所有 slot 帧数之和必须精确等于参考腿的总帧数**。
- 修订时**内容可变、帧数不可变**；槽内部的画面切点也必须停在原帧。
- 理由：多腿交付要求两条视频逐帧对齐。差 3 帧就是 0.1 s 的永久错位，且越到片尾越明显。
- 做法：把「画面 → 全局帧区间 → 槽内帧区间」做成一张表交给施工者，**不要让它自己算**。
  表里同时给出该画面覆盖的文案，动效才有对位依据。

## 拼接的三个条件

1. **编码参数逐项一致**：codec / profile / level / 分辨率 / pix_fmt / fps / time_base / 无音轨 / +faststart。
   开工会先定死这组参数，之后每槽都照抄。
2. 各槽独立编码，最后用 concat 解复用器 `-c copy` 拼接（不要再编码一代）。
3. 拼完必查：**总帧数、时长、无音轨**，再跑一次整条的 `check_motion.py`。

## 性能配方（决定"一晚上做不完"还是"一分钟渲完"）

同一台机器实测：逐帧写 1920×1080 PNG 的路线约 **7 帧/秒**；下面这条路线约 **100 帧/秒（约 13 倍）**。
4600 余帧的整片返修因此只花了约 46 秒。

1. **在低逻辑分辨率上作画，把整数放大交给 ffmpeg。**
   把帧以 `rawvideo rgb24` **管道**喂给 ffmpeg，用 `-vf scale=W:H:flags=neighbor` 放大。
   **绝不逐帧写 PNG**——编码与落盘是主要成本，而不是绘图本身。
2. **静态层每镜只画一次**并缓存成图；逐帧只 `copy` 缓存 + 贴活动元素。
3. **元素预算**：每镜 ≤3–5 个活动元素；全片只复用少数几套循环（走 / 传送带 / 蒸汽 …）。
   不做粒子物理、拖尾、液体模拟、二次弹跳——**少即是快，也少即是风格**。
4. **QC 抽帧，不逐帧读图**：每槽抽 5–8 帧。
5. 生成脚本要支持 `--qc t1,t2` 按指定时刻重出单帧，返修时便于核对；抽帧图看完即删。

## 资产与一致性

- 角色、道具、材质做成**参数化函数**（角色带 `pose` / `prop` 参数，材质做成纹理配方），
  不要每个镜头各写一套——返修时只改一处。
- 全片共用一套调色板，以及"层"的约定：前景剪影 / 中景主体 / 远景雾化（空气透视）。
- **可重跑等价**：改了绘制管线后，重跑已批准的静帧资产并逐张比对哈希，
  确认没有反向改动已批准的图。改管线不许悄悄改画面。
- 一个 slot 一个子代理；**返修复用同一个子代理**——它的上下文里有资产结构、失败经验与风格判断。
- **同一目录同一时刻只允许一个写入者**：并行只并行到不相交的目录，并明确"这个文件此后归谁维护"。

## 字幕安全区

- 开工前就定：**哪一条带不许放重要元素**（常见是下方 1/5）。写进施工规格，逐槽执行。
- **程序化检查，不靠肉眼**：抽帧后统计该条带内"有色相像素"的占比。
  地面纹理、桁架剪影、暗部底纹属允许项（被字幕压住无所谓）；人物、道具、动作属违规。
- 全片扫一遍找最坏点——只看几张一定会漏。发现违规就上移该元素，不要指望字幕避开它。

## 逐画面返修循环

成片之后，作者要能**逐画面**给方向。做一个画面级审阅页，比在聊天里描述省一个量级：

- 一屏一个画面：**内嵌该画面的真实动画片段**（从交付的视觉腿里切出来），
  **不是静帧**——作者看得到运动才给得出画面意见。
- 片段下面挂**这一画面里说的那几句文案**，按字幕断句拆成整行，可逐行批注；
  再给一个整屏的画面反馈框。
- 极小的本地服务把反馈写进 JSON，代理直接读；另给一个"复制全部反馈"的兜底按钮。
- ⚠️ **文案与画面的对应必须按"时间重叠最多"分配**，不能按"cue 起点落在哪个区间"：
  字幕链的累计时间与实测段时长之间有约 **0.03 s 的累计舍入差**，
  边界附近的 cue 会掉进上一个画面。曾因此让某一屏拿到 0 行、相邻两屏整体错位一格。
- 抽帧与切片要加**指数退避重试**：云同步目录里写大媒体文件会偶发失败（见 GOTCHAS #5）。

## 交付与验收

- 多腿交付：**视觉腿无声**、口播腿带音轨、SRT 独立；两条视频同帧率同帧数；
  交付说明写清怎么叠、哪条腿出声、字幕安全区在哪。
- 视觉腿交付前：逐槽 + 整条 `check_motion.py`；`check_screen_text.py`（画面里只放内容，不放处理手法）。
- 抽首 / 中 / 尾帧**自己看一眼**：机器通过不等于画面成立。这一步不能外包给校验脚本。

## 关键 learning（一句话版）

1. **帧数是合同。** 修订可以改内容，不能改帧数；槽内切点也不许动。
2. **拼接靠参数一致**，不靠运气；拼完必查帧数、时长与"是否无声"。
3. **低分辨率作画 + 管道喂 ffmpeg + 静态层缓存** 是两位数的提速，也是整条路线成立的前提。
4. **元素预算**是速度的另一半：少即是快，少即是风格。
5. **字幕安全区提前声明并程序化扫**，不能靠眼睛。
6. **文案落画面按重叠分配**；按起点分配在边界必错位。
7. **返修复用同一个子代理**；并行只并行到不相交目录。
8. **可重跑等价**：改管线不许悄悄改掉已批准的静帧。
9. **一个绿色的 check 不等于画面成立**——最后必须有人看帧。
