# 0001 · 保留 HyperFrames 底座，吸收结构化视觉隐喻与音画卡点方法论

**Status**: superseded by ADR-0006

我们决定继续留在 HyperFrames 无头浏览器渲染与审阅工作台底座上，不在 v2 迁移至 Remotion 或维护双引擎；但全面吸收优秀代码动画工作流中的高聚焦视觉隐喻（极简主角与大字留白）和帧级音画卡点方法论。

## Considered Options

- **全量或部分迁移至 Remotion**：重用 React 参数化镜头组件生态成本高，且会击穿现有基于 HyperFrames 活舞台的审阅控制台与 619 条测试验证体系。
- **留在 HyperFrames 并升级方法论**：视频渲染瓶颈在于浏览器引擎与 AI 对 HTML/SVG/GSAP 的理解而非壳框架本身；保留稳定底座可把全部工程投入集中在视觉语法、声音与交互痛点上。

## Consequences

- 全部渲染、活舞台预览与审阅桥协议零回归继续工作。
- 后续若真实出现跨片可复用复杂 3D/物理组件需求，可在现有底座之上补充少量通用积木模板，或单独开立新决策再行评估。
