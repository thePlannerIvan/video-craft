# Style Profile: 单色新粗野主义·架构图解

这是 `monochrome-new-brutalism-diagram` 主题的创作层规则。主题的 `tokens.css` 只负责颜色、字体、圆角、阴影、舞台密度和动效气质；本文件负责把这套风格正确地用于知识型视频。

## Core idea

把模型关系画成画面主角，而不是用标题、说明卡或小方框代替模型。默认母语法是：

```text
资料 ──→ [ Pipeline ] ──→ 产出
                         ↑
                        Wiki
```

- 输入、资料、素材和项目语境放在左侧，通常使用灰面节点。
- Pipeline、流程、分析动作或处理过程放在中间，通常使用最大、最重的黑面节点。
- Wiki、专业知识、隐性经验或可替换知识层放在流程上方，用垂直箭头指向 Pipeline。
- 右侧必须写字幕正在讲的产出：方案、结果、洞察或工作产出；不要默认写成 `Skill`。
- 只有当字幕明确讲对比、分支或迁移时，才改变母语法的结构。

## Composition guardrails

- 16:9 画布中保留左侧人物视频安全区；即使没有人物素材，也保留占位框。
- 人物区约占左侧 520px，右侧是模型主场；不要把模型缩成右侧小卡片。
- 去掉包住模型的外层展示框，让节点、箭头和空白画布直接建立关系。
- 用一条强竖线分开“人物叙述”和“模型解释”；右侧可保留细顶部线、底部线和极弱几何角标作为舞台骨架。
- 不用卡片网格填空，不把每个词都做成小方框，不堆章节标题和编号。

## Visual grammar

- 0px 圆角；5–7px 节点边框；12–18px 纯黑偏移阴影。
- 横向连接用粗线加三角箭头；Wiki 到 Pipeline 用垂直箭头。
- 黑 / 白 / 灰承担语义层级：灰面输入、黑面核心流程、黑面或高对比面输出。
- 不引入第二个彩色 accent；不要用柔和投影、渐变、霓虹或复杂装饰抵消几何力量。
- 核心节点和箭头要在缩略画面中仍然可读；宁可减少标签，也不要缩小模型。

## Text and motion

- 文字只给节点命名，完整口播交给字幕；标题只在确实有结构价值时出现。
- 中文用粗重无衬线，英文和元数据用 Inter / 等宽字体；混排标签先保证完整可读。
- 动效按“输入出现 → 连线建立 → Pipeline 落位 → Wiki 指挥 → 产出出现”的关系顺序揭示。
- 用 seek-safe 的单一 paused GSAP timeline；优先短促 ease-out / power2-out，不用 overshoot、随机数或无限循环。
- 换页不能出现黑场、黑闪或入场时的误导性空白；对最终 MP4 做 step 边界抽查。

## Semantic audit

在每个 step 审查：

1. 画面表达的是当前字幕，而不是提前表达下一段内容吗？
2. 每个节点都有明确的输入、流程、知识层或产出角色吗？
3. Wiki 是否真的指挥流程，而不是被误画成输入或输出？
4. 右侧是否写成字幕中的产出 / 方案 / 结果，而不是泛化成 `Skill`？
5. 关系是否由箭头、汇入、分流和层级表达，而不是只靠标题复述？
6. 模型是否足够大，人物安全区是否仍然存在，是否出现黑帧？

## When to use

选择该主题后，在 Storyboard 阶段读取本文件；在 Composition 阶段将其作为布局、模型语法、标签精简和换页检查的约束。不要把人物安全区或 `资料 → Pipeline → 产出` 硬编码进主题 token；它们属于工作流 / 项目表达层。
