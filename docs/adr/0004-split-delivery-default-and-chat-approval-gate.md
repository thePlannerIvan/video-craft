# 0004 · 默认分轨三件套交付与会话出片授权双轨闸门

**Status**: accepted (partially superseded by ADR-0005; chat-approval drift rule amended by ADR-0006)

我们决定将同时包含真人口播轨与画面层的项目（典型如 `keyframe-svg`）默认交付形态确定为「高码率人物成片（含润色人声与音效）+ 无声纯画面成片 + 导入空隙保护字幕」三件套，仅在显式要求单视频时合流；同时保留审阅快照生成与源码零漂移硬门禁，但放行条件扩展为「审阅页人工提交」或「作者在对话中明确授权出片并写入可审计会话授权记录」二选一，并将剪辑单身份指纹升级为路径无关的规范区间结构哈希。

## Considered Options

- **继续强制合流成单视频且强制回浏览器二次点击提交**：迫使创作者在剪辑软件里重新拆分人物与画面或再次编码，且对话口头授权出片后还要切回浏览器补点按钮，产生重复机械摩擦。
- **彻底取消 `render_gate` 与源码漂移校验**：会退回未经审阅或改源后偷渲旧版的历史事故。

## Consequences

- `helpers/deliver.py` 在存在人物与画面层时默认输出三件套，并核验画面轨无声与人物/画面时长对齐；纯口播、蒙太奇或 `--no-person` 按各自路线产出对应文件，显式 `--composite` 仍输出单轨合流成片。
- 对话中作者明确允许导出时可通过 `--approve-in-chat` 在零漂移前提下写入 `chat-approval` 审计条目后合法放行；未出过审阅页或改源后未重建依然强行阻断。
- 复制或重命名项目目录不再因剪辑单绝对路径变更而触发伪 `mismatch` 阻断，同时对存量历史字节指纹保持只读兼容。
