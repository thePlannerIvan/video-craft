# Spec: Video Craft v3.1 — 静态全绿下的工程门禁闭合、失效沉积清扫与上下文防退化加固

## Problem Statement

在 `video-craft` 完成 v3-Remotion 换代与既有单测、结构校验、模板自检及评估用例静态全绿之后，对照代理文档工程规范与技能结构验收准则进行深查，仍暴露出六类静态绿灯完全放行、但在真实跑片与多轮迭代中会稳定制造方差与误操作的问题：

1. **Remotion 工程默认视觉体检存在门禁断层**：统一画面体检入口在识别到 Remotion 动效引擎后，默认全量模式下仅跑了活舞台检查、类型编译、分镜对账与过程词筛查，直接跳过了视觉质量检查器，且视觉质量检查器自身仍只扫描历史兼容目录；实机录屏防进静态资产目录的守卫也未覆盖 Remotion 静态资产区，导致最小字号、安全区侵入与实机录屏越界在默认自检中静默放行。
2. **务实会话出片授权存在被模型提前收工误触的风险**：当前允许已建审阅快照的工程在获得对话指令后携带授权标志直接出片，但授权说明仍为可选默认值且无原话核验要求；同时制作阶段契约中多个核心步骤缺少明确可判定的完成线，且第 8 步工程态审阅终点与第 10 步交付步骤同屏可见，容易在用户仅表达“修改后再看看”时被后续交付步骤拉扯提前触发出片。
3. **文档与代码出现直接矛盾，且大量历史沉积仍在污染主视线**：字幕与音频手册仍写着早已禁用的自动多后端回退顺序；主流程参考文档与时间轴手册残留大量旧引擎语法与旧目录输出示例；踩坑防线文档正文仍滞留已冻结旧引擎的专属条目、与画面声景及会话出片授权最新裁决相抵触的旧条以及违背自身规约的硬编码行号；评估用例矩阵仍残留已退役的互斥路线标识与不存在的文档名称。
4. **核心规则跨文件整段复述且章节指针大量断链**：Remotion 四道门禁、画面声景与会话出片授权等规则在五至九份文档间反复展开，而踩坑防线与时间轴手册中存在十五处指向已删或已改名章节标题的断链指针；现有测试只检查文件是否存在，不校验章节标题、退役术语、本机路径泄漏或与代码相悖的回退描述。
5. **主入口信息层级倒置且上下文触发指针偏弱**：主入口顶部被低频首次环境配置与本机父级单仓路径泄漏占据，高频的半成品重入起点路由表被挤到末尾，内部能力矩阵与步骤表存在重复且单元格过长，触发描述仅罗列概念名词而未按独立分支前置创作者日常使用的自然语言引导词。
6. **命令行细节缓存与纯禁令过多挤占注意力**：工具参考与音频手册抄录了本应由命令自带帮助持有的参数列表与内部声学均衡器数值；全库文档堆叠了过量纯禁令措辞却缺少对应的正向目标动作。

## Solution

以「机械门禁闭环先于文字叮嘱、唯一权威出处消除重复沉积、主入口按重入频率重构层级、静态护栏锁死回流」为原则，推进五项协同加固：

- **闭合 Remotion 视觉质量与实机录屏门禁**：打通统一画面体检入口、视觉质量检查器与 Remotion 场景源码及执行分镜的衔接，确保最小字号、安全区边界与实机录屏禁入静态资产目录在默认体检下真实生效，并修正阶段手册中的错误参数示例，同时保持冻结兼容层零回退。
- **加固会话出片授权护栏与明确阶段完成线**：在不推翻务实会话出片授权的前提下，把授权说明升级为强制非空且拒绝默认占位符的原话凭证；为制作阶段契约补全各步显式可检查完成标准，并在审阅与交付分界处增加明确授权与普通返修的正反例，遏制提前收工。
- **升级静态指针与卫生护栏**：把人工判断指针引号章节存在性检查、禁止正文字段硬编码行号、拦截已退役文件名与枚举、拦截本机父级单仓路径泄漏及与代码相悖的假自动回退描述写入自动化测试，让文档退化立刻红灯。
- **彻底清扫失效沉积并收敛唯一权威出处**：统一清理与代码冲突的转写回退描述、非兼容节的旧引擎语法残留及过期踩坑条目（迁入历史迁移索引并对齐最新裁决）；将四道门禁、会话出片授权与分轨交付、人声润色与画面声景分别收口到唯一权威手册，其余文件只保留单行上下文指针，同步删去参数与内部数值缓存并转为正向目标表达。
- **重构主入口层级、锐化触发指针与对齐评估用例**：把主入口触发描述改写为前置高频引导词的按分支触发指针；将首次安装密钥表下沉至安装说明、前置半成品重入起点路由表并合并内部重复表格；清理并补充评估用例矩阵以全面覆盖本轮加固后的防回归行为。

## User Stories

1. 作为创作者，我希望在新建 Remotion 动效或混合实机录屏工程上运行默认统一画面体检时，字号过小、元素侵入人物区或字幕安全区以及把原录屏塞进静态资产目录等缺陷能被当场拦截，不再出现体检全绿却带病进入审阅或渲染的情况。
2. 作为创作者，我希望视觉质量检查器对 Remotion 工程与实机录屏分镜依据画框唯一几何真源执行一致核查，而历史旧引擎工程仍保持既有冻结兼容检测不变。
3. 作为创作者，我希望只在我在对话中明确指示“改完这处直接导出”时才触发会话出片授权，系统必须记录我的明确授权原话依据而不是自动填入默认占位语，从而防止仅仅提出返修意见时被误导出。
4. 作为执行技能的 Agent，我希望制作阶段契约的每一步都有清晰可验证的完成判据以及“可继续 / 须回谈 / 停止在审阅态”的明确边界，从而不会受后续交付步骤诱导而过早结束或越权出片。
5. 作为创作者，我希望在需要调用技能进行剪口播、做动效、画框设计、实拍混剪、实机录屏、声景配音、审阅返修或导出成片时，主入口触发描述能够准确匹配我的日常表达并可靠唤起对应能力分支。
6. 作为带着半成品中途切入的 Agent，我希望打开主入口就能在最靠前的位置看到“常见来料起点与当前步定位表”，立即跳转到对应阶段和入口，而不必先穿过低频的首次安装配置表。
7. 作为开源使用者，我希望主入口与安装文档中不再出现任何维护者本机父级单仓路径硬编码，所有环境与密钥配置说明都收敛在安装指南中且开箱可移植。
8. 作为执行技能的 Agent，我希望主入口内部不再有重复并列的两张能力与流程表，也没有塞满两百字的超长表格单元，从而在一眼内看清固定底座、可选能力叠加与正交画框的关系。
9. 作为执行技能的 Agent，我希望查阅字幕与音频手册时看到的转写顺序与真实代码行为完全一致，不会再被文档里残留的旧自动回退说明误导去依赖已被禁用的通用多模态模型。
10. 作为执行技能的 Agent，我希望在制作阶段契约、视觉语法与时间轴手册中只看到面向 Remotion 主引擎的标准流程，旧引擎只读兼容细节只集中在专设的兼容小节中，不再混杂在新建路径示例里。
11. 作为长期维护者，我希望踩坑防线文档正文只保留当前真实仍可能犯的错误，所有已冻结旧引擎的专属条目都体面迁入历史迁移索引，同时现存条目与画面声景、会话出片授权的最新裁决保持完全一致。
12. 作为长期维护者，我希望每一条人工判断指针引用的章节标题都在目标文档中真实存在，再也不会出现点过去找不到对应标题的断链指针。
13. 作为长期维护者，我希望四道门禁、会话出片授权、人声润色与画面声景各自只在一份权威手册中完整阐述，其他文档只放简短指针，从而做到后续只需改一处、不再改一漏八。
14. 作为执行技能的 Agent，我希望工具手册和音频手册不再重复抄录脚本内置帮助信息或内部声学均衡器参数数值，而是直接指引我在需要时查看命令行自带帮助，确保文档永不过期。
15. 作为执行技能的 Agent，我希望文档更多用清晰的“正向目标动作”代替密密麻麻的纯禁令列表，只在真正不可逆的硬护栏处配正反例，降低误解与反向提示干扰。
16. 作为长期维护者，我希望仓库卫生测试与踩坑防线测试能够自动抓出断链章节标题、硬编码行号、退役文件名、退役路线枚举、本机路径泄漏以及违背代码的假回退说明，在提交前就把文档退化拦住。
17. 作为技能评审与验收者，我希望评估用例矩阵使用当前能力组合术语而非已退役路线名，并且专门包含“Remotion 视觉质量门禁不可跳过”和“缺少明确授权原话不得私自触发会话出片授权”的对抗用例。
18. 作为项目所有者，我希望全部修改严格只在技能库主源码目录完成并跑通全量测试与静态门禁后再统一发布同步至本地各运行环境及公开仓库，保持两端逐字节一致。

## Implementation Decisions

### 一、Remotion 视觉质量与实机录屏门禁闭合

- **统一画面体检默认路径接通**：统一画面体检入口在自动识别到 Remotion 动效引擎后，默认全量检测模式必须串联执行视觉质量与实机录屏合规校验，而不再仅停留在类型编译与分镜对账；历史冻结旧引擎分支保持原有检测序列完全不变。
- **视觉质量检查器面向 Remotion 与实机录屏扩域**：视觉质量检查器针对 Remotion 场景源码树收集可校验源文件与样式定义，复用既有的画框唯一几何真源（人物孔位、舞台安全区与字幕安全区）执行最小字号、安全区侵入、未注册外部字体与实机录屏边界核查；当执行分镜包含实机演示片段时，除继续拦截将原录屏放入历史静态资产目录外，同等严禁将原录屏放入 Remotion 静态资产目录。
- **阶段文档调用契约修正**：修正制作阶段契约中对统一画面体检单选项的误导性多值拼接写法，统一标注为单次传参或默认全量自检，避免模型按错误语法传参导致调用失败。

### 二、会话出片授权防误触发护栏与阶段完成线

- **会话授权强制原话凭证**：延续既有务实会话出片授权架构裁决（只要审阅快照已存在且获得作者当轮明确导出指示，允许在审阅微调后直接写入最新实时源码指纹审计记录并放行导出），同时收紧渲染闸门与交付入口的授权接口——开启会话出片授权标志时，授权说明参数由可选默认占位升级为必填凭证，禁止空字符串或默认敷衍占位语，必须传入作者当轮在对话中明确指令出片的原话依据；缺失或仍为占位说明时渲染闸门直接返回非零拦截。
- **阶段契约补全完成线与防提前收工护栏**：在制作阶段契约中，为所有尚未声明可检查完成标准的步骤补全明确的完成判据（明确产物体、验证方式、保留在当前阶段还是交回上游），并显式规定第 8 步工程态审阅终点后的停止边界；在审阅与交付衔接处新增清晰正反例，区分“明确要求改后直接出片”（允许授权）与“仅提出修改意见或尚未拍板”（必须停留在重建审阅态），抵消后续交付步骤带来的提前收工拉力。

### 三、指针完整性与退役沉积静态门禁

- **踩坑指针章节存在性与零行号门禁**：在踩坑防线测试套件中新增两条机械检查——第一，凡使用人工判断指针且引用了具体章节或小节标题的条目，自动核验所引标题在目标文档中真实存在；第二，严禁踩坑防线正文硬编码源码行号引用，防止代码微调后文档指针静默失效。
- **仓库卫生与静态防回流门禁扩展**：在仓库卫生与链接完整性测试套件中新增四项确定性防回流守卫——第一，跨文档检查引号标注的参考手册小节引用在目标手册中真实存在；第二，拦截已退役交接或交付文档名、已退役互斥路线标识与旧字段称谓在现行主文档及评估用例矩阵中的回流（历史裁决、历史迁移索引、退役术语表与明确标定的历史只读兼容节除外）；第三，拦截技能文档与说明中出现维护者本机父级仓库目录路径硬编码；第四，拦截声称转写自动回退链路包含通用多模态后端的错误描述。

### 四、失效沉积清扫与唯一权威出处收敛（Single Source of Truth）

- **修正事实矛盾与清理旧引擎残留**：将字幕与音频手册中与代码实现相反的自动回退顺序改回与真实行为完全一致（首选豆包流式语音识别，无其凭据时仅自动尝试可选第二词级引擎，明确指出通用多模态后端不参与自动回退且仅用于非词级场景的显式调用）；将制作阶段契约、视觉语法与时间轴手册中残留的旧引擎页面语法、标签写法及旧引擎默认输出路径示例全部迁回标准 Remotion 工程结构，仅在明确标定的历史只读兼容小节保留冻结老工程说明。
- **踩坑防线瘦身与裁决对齐**：将踩坑防线正文中专属于已冻结旧引擎的条目整体迁出至历史迁移索引（保持编号不复用并更新索引说明），同步更新与画面声景双轨裁决及会话出片授权最新裁决相冲突的现行条目，清除正文中的硬编码源码行号，修复全部十二处失效的人工判断章节标题引用。
- **单一权威收敛与去缓存化**：确立核心专题的唯一权威出处——Remotion 引擎规范、外部运行壳与四道门禁细则由动效引擎手册唯一持有；审阅双通道、会话出片授权边界与分轨交付细则由审阅交付手册唯一持有；人声润色除吸气声与画面声景细则由字幕音频手册唯一持有；所有脚本参数与内部声学均衡器细节交给命令行自带帮助自证，工具手册与音频手册删去重复抄录的参数枚举与均衡器参数缓存；主入口、阶段契约与其余手册只保留单行上下文指针。同步排查评估各文档高密度禁令段落，在不削弱硬护栏的前提下改写为“正向目标行为 + 必要硬防线”。

### 五、主入口信息层级重构、上下文指针锐化与评估集对齐

- **上下文触发指针锐化**：重写主入口触发描述，将创作者真实常用的引导词（剪口播、加字幕、做动效、画框、混剪、实机录屏、配声景、审阅返修、导出成片）前置到首段，按独立使用分支与半成品重入场景组织触发条件，并清晰划定与上游制片总控及静态页工具的衔接边界。
- **信息层级重排与结构压缩**：把低频首次安装才需要的环境变量密钥表与运行环境准备下沉至安装说明，同时删除本机父级单仓路径泄漏；将高频的“常见来料起点与对应步定位表”提至主入口靠前核心位置以便半成品重入；把主入口内重复列举能力与入口的两张表格合并为单一清晰的「底座 × 可选能力组合 × 正交画框」总览，拆散超长密集单元格并把详细执行动作收归对应权威手册指针。
- **评估用例矩阵对齐与防回归增补**：将评估用例矩阵中的已退役路线标识、已退役参考文档名以及过时的旧引擎资产目录描述统一对齐至 v3 能力组合、Remotion 外部运行壳与现行权威手册体系；新增专门针对本轮修复的两条防回归用例——核验 Remotion 工程在默认自检下必过视觉质量与实机录屏门禁、以及缺少作者当轮明确授权原话时严禁绕过审阅或擅自填入占位符触发会话出片授权。

## Testing Decisions

本轮验证完全依托既有高层黑盒接缝进行验收，仅测试外部可观察行为、退出码与机器可读输出，不针对内部私有函数编写白盒单元测试：

1. **接缝一：顶层命令行工具进程黑盒接缝**
   - **测试范围**：统一画面体检入口（针对 Remotion 工程与实机录屏夹具的默认全量检查及单项质量检查）与交付/渲染闸门入口（会话出片授权原话凭证校验）。
