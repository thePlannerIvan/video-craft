# 能力系统与方法论（v3 方向）

这份文件记录 2026-10 一次真实事故后的架构取向：**不再声明固定路线，也不建调度框架**。
模型负责选择和组合，工具负责准确执行；只有少数共享事实需要唯一主人。

事故摘要：一段 75 分钟录屏 + 27 页 SVG，被当成"新路线"，自写 6 个脚本，绕过 page/recompose
两条既有能力和全部 gate，重踩四条旧 gotcha。页面资产、snapshot、recompose 当时都在库里。

## 1. 能力（tools）

能力按动词划分，接口是 CLI + 文件，不依赖隐藏上下文。清单见 `references/tools.md`；
这里只规定新增能力时的边界：

- 一个能力只拥有一件事；输入输出能被另一条命令复现。
- 能力**不决定用户要走哪条路**，只返回结果与失败原因。
- 检查放在真正需要它的底层操作旁边（渲染、编译预览、导入、交付），不集中成一个调度器。

v3 已补的两个缺口：`helpers/edl_from_keep.py`（keep-list → 静音吸附 EDL）、`helpers/audio_mix.py`（人声/BGM/duck/响度 → 单一混音出口）。

## 2. 能力包（docs only，可叠加）

能力包是**给模型选择的工作记录**，不是执行许可清单，也不是互斥路线。常见包：

| 包 | 判据 | 依赖能力 | DoD（点名检查） |
|---|---|---|---|
| 保真页面 | 作者要求逐像素保留那版页面 | 页面导入、时间轴、页级动效 | `check_parity` / `check_screen_text`；**页面没有元素级动效时 `check_motion --expect-still`**（默认判据会把静止页误报成“时间轴没注册”） |
| 重排画面 | 板子只作参考，允许为动效重排 | recompose、composition | `check_overlay` / 人物位不被占用 |
| 叠层 | 已有成片，只叠字幕/图形 | 合成、字幕 | `check_overlay` / `verify_av` |
| 人物层 | 需要一个与声音严格同步的小窗/角落人像 | 时间映射、FFmpeg overlay | `check_overlay`（人像区不压字）+ judgment：同一帧对比源与成片 |
| 字幕 | 需要上屏文字 | 字幕生成 | 内烧需 libass；缺则外挂 SRT，并在交付说明里写清 |
| 音乐床 | 需要 BGM | 单一混音出口 | `audio_diag`（停顿时可闻）+ **进 composition 前先 `audio_mix`/`audio_fix` 到 -14 LUFS**（composition 不会替你归一）+ judgment：整体听感 |

没有"必须四选一"：这次任务就是 保真页面 + 人物层 + 外挂字幕 + 音乐床 叠加。
包的记录写在 `edit/project.md`（人读），**不新增 project.json**；只有被工具实际消费的字段才值得机器化。

## 3. 共享事实的唯一主人

时间映射、混音、页面意图、来源与交付件的唯一主人登记在
[architecture.md](architecture.md) 的「共享事实」一节——这里是选择题，不是第二份契约。

## 4. 探测与降级

`helpers/probe_env.py` 只报告能力（ffmpeg 滤镜、字体预算、残留进程、font cache），
不替模型决定降级，默认退 0。替换（字体子集、写 /tmp、暖缓存）可以直接做；
**改变交付合同**的替换（烧录→外挂 SRT、元素动效→整页）由模型结合用户意图决定，
并把结果写进交付说明与项目记录。工具执行失败就如实失败，不用"静默损坏才阻断"当通用语义。

## 5. 审阅

两个业务审阅契约：**剪辑选择**与**画面/合成反馈**；共享宿主、提交、快照绑定、收件接口。
不同项目可以有不同的多片导航与布局，只要反馈能回到正确的片、单元与快照。
"模板数量"不是架构指标；"一次多片切换 + 反馈往返"才是验收。

## 6. 指纹

交付指纹的**目标**是从生成时实际消费的输入与显式交付清单取得；当前交付侧仍是 page 硬编码清单（raw-deck 项目需手动登记来源），不反向依赖审阅清单；
媒体按内容哈希（路径+大小+mtime 不是身份），交付件递归遍历（`成品/subtitles/*.srt` 也要算）。
