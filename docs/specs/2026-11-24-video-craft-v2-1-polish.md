# Spec: Video Craft v2.1 — 分轨默认交付、会话授权闸门、极简审片与全链路纠偏

## Problem Statement

创作者在《非遗三个圈_v2》真实端到端出片实测及技能目录通盘复查中，遇到四类直接打断手顺、造成重复劳动或隐蔽失效的问题：

1. **交付形态与真实剪辑习惯倒置、跨端授权重复确认**：成品交付入口默认将人物与画面硬焊成单轨视频，不符合创作者将「人物成片（含润色人声与音效）+ 无声画面成片 + 剪映导入安全空隙字幕」拖入剪辑软件自行微调合并的工作方式；创作者已在审阅并回到对话明确下达「允许导出」后，仍被渲染闸门强迫切回浏览器页面再点一次提交按钮；当项目目录复制或重命名演进新版本时，即使剪辑单区间与成片字节完全一致，交付核验也会因绝对源路径变化引起哈希变动而报错阻断。
2. **画面审阅页残留两代界面叠层与跨阶段死按钮**：画面审阅页右上角仍悬挂早期的「逐字剪辑」按钮，在独立浏览器中点击完全无法打开目标页面，且工作流上与画面审阅阶段职责冲突；页面右侧仍堆叠着与现行四档视觉语法脱节的「逐句五档画面密度」开关矩阵及旧版画布元素直改工具条，异常状态下还会弹出内部脚本名与宿主机制黑话；逐字剪辑页在独立浏览器保存后缺乏明确闭环状态提示。
3. **口播剪辑与音频主干存在隐蔽脱节**：口播剪辑总入口虽然在说明书中被指定优先调用豆包流式语音识别 2.0，但实际代码仍只调用旧版转写脚本，根本不会触发流式词级识别，且报错时可能静默降级至已被明确禁止的通用多模态模型；脱离侧栏插件在本地起页面时，口播剪辑审阅命令不会自动拉起本地浏览器宿主；两支音频公开入口预设开关名不统一且混音入口默认关闭播客音色，极易漏开或被模型重复压缩两次。
4. **内部模块收口后路牌失修与废料残留**：约六十余个共享实现下沉至内部目录后，共有四十七处错误提示、帮助文本与说明文档仍打印旧顶层脚本路径，一旦某步出错模型按提示执行就会直接找不到文件；技能包内仍残留空工作目录、系统隐藏文件与不再需要的历史施工过程记录。

## Solution

以「顺应真实出片手顺、精简审阅界面到只剩高频刚需、补齐底层链路断点与过期路牌」为原则，在已有 v2 稳定底座上完成 v2.1 精准收口：

- **默认分轨三件套交付 + 会话授权双轨闸门 + 路径无关剪辑指纹**：对于包含真人口播与画面层的项目，交付入口默认输出「人物成片（高码率原人物流 + 播客音色与克制音效）+ 纯画面无声成片 + 自动修正导入空隙的外挂字幕」三件套，纯口播、蒙太奇或无人物项目按对应路线只输出必需产物，并保留显式单轨合流开关；保留审阅快照生成与源码零漂移硬门禁，放行依据改为「审阅页人工提交」或「作者在对话中明确授权出片并写入可审计会话授权记录」二选一；剪辑单指纹改为对规范化后的片段结构计算哈希，消除目录拷贝或重命名带来的误报。
- **极简审片工作台与清晰浏览器闭环**：彻底移除画面审阅页右上角跨阶段死按钮、右侧五档画面密度面板、旧版画布元素编辑条及所有残留工程黑话，仅保留分章跳转、自适应 16:9 舞台、字幕/倍速/播客音色 A-B 切换以及右侧精简本段/整片意见框和历史记录；逐字剪辑页在独立浏览器保存后展示明确的「已保存并可回对话继续」闭环反馈。
- **主干链路对齐与仓库清场**：口播剪辑总入口正式接通豆包流式语音识别 2.0 作为默认首选并彻底封死向非词级多模态模型的静默降级，同时为本地浏览器运行补齐自动拉起宿主能力；混音出口默认开启 C 档「播客浑厚」人声预设并消除与单轨预处理入口的重复压缩风险；批量修复全仓过期内部路径提示、清除空目录与无用过程文件，并补充一条简洁架构裁决与词汇表更新。

## User Stories

1. 作为创作者，我希望在《非遗三个圈》这类「真人口播 + 动效画面」项目中，默认一口气导出人物成片、纯画面成片与字幕三件套，以便直接拖进剪辑软件微调合并，而不必每次额外口头纠正。
2. 作为创作者，我希望人物成片保留高码率原人物流并直接封装进升级后的播客音色与克制音效，以便人物画面清晰度不降级、人声直接达到广播质感。
3. 作为创作者，我希望画面成片保持纯视频无声轨，以便与人物成片同时放进剪辑软件多条轨道时绝不产生双倍回声或重音叠加。
4. 作为创作者，我希望交付出来的字幕自动经过剪映与 PR 导入空隙保护处理，以便直接拖入时间线就能严丝合缝且不错位。
5. 作为创作者，我希望纯口播项目、蒙太奇混剪项目或声明无人物轨的项目在默认交付时只产出自身真正需要的成品文件，以便不凭空制造多余或空白轨道。
6. 作为创作者，我希望偶尔需要直接发群看一版合流视频时，仍可以通过一个显式合流开关导出单轨视听合成成片，以便兼顾快速预览与正式后期两种用途。
7. 作为创作者，我希望只要当前版本先出过审阅页且源码未在审阅后悄悄改动，当我在对话里明确说出允许导出时就能直接放行渲染交付，而不必再被迫切回浏览器补点一次提交按钮。
8. 作为创作者，我希望系统把我在对话中的明确导出授权写入一条结构化审计记录，以便既不卡人又能守住「未审不偷渲」的防线。
9. 作为创作者，我希望即使从旧工程目录复制出一份新版本目录进行迭代或重跑交付，只要剪辑区间与源片没变，交付核验就不会因为文件夹路径变长而误报剪辑单不匹配。
10. 作为创作者，我希望只要真的改过任何剪切起点、终点、增删段或更换源片，规范剪辑指纹就必须立刻发生变化并精准拦住过期实测数据，以便真实变化绝不漏放。
11. 作为创作者，我希望画面审阅页拿掉右上角点不开也用不上的「逐字剪辑」死按钮，以便工作阶段边界清楚、不再在画面阶段看见残废控件。
12. 作为创作者，我希望画面审阅页删掉右侧「逐句五档画面密度」整排开关矩阵和旧版画布元素直改工具条，以便整个页面退回简单好看的极简审片状态。
13. 作为创作者，我希望精简后的画面审阅页依然完整保留分章快速跳转、自适应 16:9 舞台、字幕开关、倍速播放、`播客音色 / 纯干声` 一键对比以及右侧「整片 / 本段」文字反馈与历史记录，以便审片与提修改意见一次搞定。
14. 作为创作者，我希望画面审阅页无论正常播放还是遇到预览服务异常，都不再暴露脚本文件名或内部桥接术语，以便界面上出现的一切文字都面向使用者而非工程师。
15. 作为创作者，我希望逐字剪辑页在没有侧栏插件的独立浏览器里点击保存后看到清楚的成功提示，以便确信修改已经可靠落盘并可以回到对话继续下一步。
16. 作为创作者，我希望模板静态守卫随着页面精简同步升级并保留自证样本，以便删掉的多余控件永不回流，而新约定的极简结构受自动保护。
17. 作为创作者，我希望运行口播剪辑预处理入口时默认优先走豆包流式词级识别，并在缺少语音凭据时停下明确提示配置方法，绝不静默降级去调会飘移时间戳的通用多模态模型，以便词级时间基准始终可靠。
18. 作为创作者，我希望在独立对话环境下运行口播剪辑审阅命令时，即使没有侧栏插件也能自动拉起本地浏览器宿主并给出访问地址，以便不再手动拼底层内部脚本路径启动页面。
19. 作为创作者，我希望统一混音唯一出口默认自动应用 C 档「播客浑厚」预设并仅在需要原声时传一键纯干声参数，以便正常出片不再因为忘传参数而悄然丢失人声润色。
20. 作为创作者，我希望人声预处理入口与混音入口各自职责边界清晰、参数说明明确，以便不会把已润色过的人声送进混音再压缩第二次。
21. 作为创作者，我希望全仓所有报错提示与文档里不再留有已经搬进内部目录的过时脚本路径，以便任何一步排查都能按提示一次跑通。
22. 作为创作者，我希望技能目录里的空工作文件夹、系统隐藏文件和历史验收过程记录被整理清除，同时增补清晰的领域裁决记录与术语定义，以便长期维护和开源分发清爽可信。
23. 作为创作者，我希望改动完成后直接使用本次的《非遗三个圈_v2》真实长片跑通默认三件套导出核验并检查全部门禁，以便确认所有痛点已在真实项目上闭合。
24. 作为创作者，我希望全部单元测试、模板自证、规范校验与真实核验全绿之后，再统一同步至本地三个运行环境并推送独立公开仓库。

## Implementation Decisions

### 默认分轨三件套交付与路线分工
- 重构交付编排器的输出策略，区分「默认分轨三件套」与「显式单轨合流」两种交付模式：
  - 对于包含真人口播轨、画面视觉层与主音频的工程，默认模式执行分轨交付：第一路产出**人物成片**，直接无损流式复制高码率人物母版视频轨并封装主音频（含播客音色与克制音效），支持保留高码率原始人物剪辑片源优先于低码率预览片；第二路产出**纯画面成片**，对经过一致性和安全区检查的画面视觉层剥离音轨后无损封装；第三路产出**外挂字幕**，经由剪映与 PR 导入空隙保护逻辑统一修正句间间隙不小于三十毫秒后落盘交付区。
  - 对于纯口播模式、蒙太奇混剪模式或显式声明无人物轨的项目，按自身实际拥有的轨道交付对应成品（仅人物带声音成片 + 字幕，或仅无声/带旁白全幅画面成片 + 字幕），不强行拆出空人物文件。
  - 保留并统一提供显式合流参数，在用户明确需要单一视听成片用于预览分发时才将人物贴回画面左侧并合成单一成品文件；交付核验报告中同时登记实际输出的分轨文件清单、各自音画流规格与来源指纹。
- 严格保留原有前置与后置质量约束：无论分轨交付还是合流交付，渲染前统一执行环境检查、四档视觉分拍表校验、无头浏览器体检与动画目标校验；渲染后逐一核验画面层抽帧一致性、实机演示同轨无损拼合、分辨率、帧率、音视频时长对齐（人物轨与画面轨差值控制在半秒以内）、人物成片存在立体声音轨、画面成片不含音轨、首中尾非全黑帧以及字幕安全区无内容侵入。

### 渲染闸门双轨放行与会话授权留档
- 维持「源码未漂移的当前审阅快照」作为交付前提：若项目尚未构建当前审阅快照，或审阅之后核心源码、剪辑单、字幕及声音素材清单发生任何变动，渲染闸门依然强行阻断交付，要求先更新审阅快照。
- 将通过放行依据从「仅限浏览器提交文件记录」拓展为合法的双轨制：
  1. 存在对应当前快照的审阅页人工提交记录（既有路径）；或
  2. 交付命令收到显式的会话授权标志与批准摘要说明。收到该参数后，闸门先校验当前审阅快照有效且源码清单零漂移，随后自动向审阅提交记录追加一条带来源标记、当前快照标识与批准时间的审计记录，再放行后续渲染与合成。
- 在技能说明与命令行契约中定死红线：会话授权参数仅允许在作者当轮对话已明确表达允许导出成片、并实际阅过当前版本后由代理传入，严禁任何内部流程在未获授权时自动注入该参数。

### 路径无关的剪辑单规范指纹
- 重新定义剪辑单规范指纹算法：提取剪辑单中的核心结构要素——对源视频映射仅抽取文件名或去绝对路径后的稳定源标识并按键排序，对每个保留片段提取源标识、规范舍入的起止时间戳以及可选的节拍归属标签，忽略用户本地根目录、项目目录改名与拷贝路径差异、非时间字段注释顺序及空白换行格式变化，再对该规范序列化结构计算哈希摘要。
- 实测时长记录匹配逻辑实行温和向后兼容：匹配渲染记录条目时，先比对规范结构哈希，若未命中则兼容比对原有原始文件字节哈希（存量已渲染旧工程零破坏）；写入新实测渲染记录时一并写入规范结构哈希；只要任一保留片段的增删、起止边界、源片文件名或排列顺序发生改变，两套哈希均立刻失效并严格拦截。

### 画面审阅页极简重构与逐字页本地保存提示
- 清理画面审阅页模板交互面至「极简审片工作台」形态：
  - 移除顶部跨阶段跳转按钮及其关联的失效占位容器与死监听；
  - 移除画布上方历史遗留的点选、框选、字号增减、微调位移与孤立元素批注工具条；
  - 移除播放控栏里的分步拆解展开开关、卡点药丸折叠开关，以及右侧整栏「逐句五档画面密度」批量操作面板与底部旧密度提交区；
  - 保留并打磨核心审片控件：左侧分章导航、自适应 16:9 舞台与居中拖拽分隔轴、播放/暂停/上下屏/倍速切换/字幕显隐/`播客音色 vs 纯干声` A-B 切换按钮，以及右侧整合后的本段/整片修改意见提交与历史反馈列表；支持整版在任意窗口宽度下将当前意见作为确认或反馈写入审阅提交契约并即时显示清晰状态气泡。
- 净化模板与逐字页的所有面向用户提示语：彻底删除残留内部脚本命令名、宿主唤醒术语与开发过程说明文字，改为自然简练的中文使用提示（例如预览加载异常、无成片、本地保存完毕等均以使用者视角表达）。
- 修复逐字剪辑页在无侧栏唤醒桥接时的保存状态回显：检测到仅运行本地宿主而无外挂侧栏唤醒通道时，点击保存并在本地写入选择文件成功后，直接以成功态呈现清晰提示「已保存修改，回对话告知继续处理即可」，不再产生仿佛未完成或需要找插件的不确定感。
- 同步更新审阅页静态守卫与多视口浏览器自证校验，新增针对已移除死按钮与冗余面板绝不复燃的负向断言，并同步刷新自证缺陷注入样本以确保全部检查项均非空转。

### 口播剪辑总入口接通首选词级识别与本地宿主回退
- 改造口播剪辑总入口的准备动作流：新增默认首选模式，当需要转写时优先路由至豆包流式语音识别 2.0，自动从当前所在技能仓库根加载语音控制台凭据，严格保留原有与现有转写文件格式一致的逐词毫秒级输出结构；若未提供语音凭据则立即停下并给出清晰的凭据配置提示。
- 明确限制通用多模态模型路径不得作为默认自动回退分支，仅当调用方显式指定对应回退选项时才允许进入该旧链路，从入口上对齐文档禁止事项与词级时间契约。
- 改造口播剪辑总入口的审阅动作流：保留只出契约文件的参数选项用于外挂侧栏集成；未传递仅出契约标志且当前处于独立对话环境时，由审阅构建环节在写完契约并校验后自动拉起本地浏览器宿主返回可直接访问的本地网页地址。

### 音频预设默认统一与防重复压缩
- 将全技能包唯一混音出口的人声预设默认值从空关闭改为默认开启「播客浑厚」预设，保证正常出片自动拥有温暖胸腔厚度与齿音收敛，同时保留一键纯干声参数与绕过降噪预设参数以随时获得未经处理的原生人声对比轨或交付轨。
- 明确划分两支公开音频工具的边界并在帮助信息与参考手册中写清唯一调用规范：人声单轨诊断处理工具仅服务于纯人声前期声学试听、盲听对照或短片段 A/B 抽样；混音唯一出口承接口播进终混的完整处理；提示或参数检测到输入已带处理标记时给出明确警示而不默许二次叠加压限。

### 全仓过时路牌纠偏、废料清理与领域文档更新
- 系统性扫描并修正全部公开工具、内部实现、HTML 模板与参考文档中指向旧顶层路径的内部脚本引用（约四十七处），统一更正为现行有效路径或顶层公开命令。
- 清除仓库显性残留废料：删除已成空壳的内部工程工作目录、误入版本的系统隐藏文件、无实际用户价值的跨上游开发对比说明以及纯历史施工流水账记录，确保外部阅读者与执行代理加载目录时只看到现行契约与清晰文档。

## Testing Decisions

本轮验证全部基于外部可观察行为构建与复跑，不针对内部私有辅助函数或中间实现细节编写脆弱测试，依托以下三条最高层现有接缝统一覆盖：

1. **接缝 1：顶层命令行进程黑盒接缝**
   - **测试范围**：交付入口、渲染闸门、规范剪辑指纹与实测时长读取、口播剪辑总入口、混音入口及全仓静态链接体检。
   - **验收策略与先例**：延续现有子进程黑盒单元测试风格，验证包含真人口播与画面层的工程默认产出三件套且人物成片有声音、画面成片无音轨、字幕空隙达标，验证纯口播及无人物项目按需仅出对应轨且显式合流参数正常产出单轨视频；验证渲染闸门无审阅快照或源码漂移必拦、审阅提交与显式会话授权参数均合法放行并落盘审计条目；验证拷贝改名项目目录后规范剪辑指纹保持匹配而篡改任意剪辑区间或源名必拦；验证口播剪辑准备阶段优先调用流式词级识别、缺凭据报错而不静默调通用多模态模型，审阅阶段支持本地宿主拉起；验证混音默认开启播客预设且一键纯干声确为原样响度；增加全仓静态扫描检查，确保零过期内部脚本引用与废料文件。

2. **接缝 2：审阅页静态守卫与真实无头浏览器接缝**
   - **测试范围**：画面审阅页生成模板与静态守卫检查器、逐字剪辑审阅页。
   - **验收策略与先例**：延续现有静态守卫自证加真实无头浏览器集成测试框架，验证守卫检查集及其全部自证样本全绿通过；在真实无头浏览器加载构建后的画面审阅页，断言不存在死按钮、五档密度矩阵及旧画布编辑条，不存在工程内部黑话文本，在宽屏、半屏及窄侧栏下自适应不溢出且拖拽分隔条生效，音色 A-B 切换与保存提交反馈正常闭环；在无侧栏宿主下测试逐字剪辑页保存操作并断言出现清晰的独立保存闭环提示。

3. **接缝 3：真实长片端到端验证与多端发布对账接缝**
   - **测试范围**：《非遗三个圈_v2》真实六分钟工程副本、技能库发布总门禁与远端 GitHub 同步脚本。
   - **验收策略与先例**：先于真实长片副本上仅通过新版公开命令与规范指纹跑通默认三件套交付，实测核验人物成片响度安全、画面成片无声且帧数一致、字幕空隙合法以及整份交付核验报告全面全绿，并在 Chrome 验证精简后的审阅页；最终改动集中落库后统一运行技能库规范校验、全量单元测试、跨端同步预检与发布、密钥闸门及远端镜像逐字节核对。

## Out of Scope

- 不对底层六十七个内部脚本实施大规模合并重写，也不推倒既有逐字剪辑全局指针引擎与播放器嵌入桥核心算法，仅收口接口契约、修通主干断点与清理显性冗余。
- 不调整已经创作者盲听定案的 C 档「播客浑厚」声学参数与本地内置八个 CC0 音效素材库。
- 不修改上游制片总控及蒙太奇剪辑路由的镜头拆解核心算法。
- 不重新设计《非遗三个圈_v2》的既有矢量动画结构与文案。
